# Armenia AI Guide — Инструкция по базе данных

Как **обнулить старую базу** и как **поднять базу с нуля** для этого проекта.

> ⚠️ Всё, что делает базу нерабочей/пустой — необратимо. Сначала бэкап (см. п.0).

---

## 0. Бэкап (сделай перед любым сбросом)

Supabase Dashboard → **Database → Backups** (или вручную):
```bash
pg_dump "$DATABASE_URL" > backup_$(date +%Y%m%d).sql
```

---

## Вариант A (рекомендую) — новый чистый проект Supabase

Самый безопасный путь: не чистить старое, а взять пустую базу.

1. Создай новый проект в Supabase (или новую пустую БД PostgreSQL).
2. Скопируй `.env.example` → `.env` и пропиши **новый** `DATABASE_URL`:
   - формат pooler-строки (порт **6543**, не 5432):
     `postgresql://postgres.xxxxx:PASSWORD@aws-0-<region>.pooler.supabase.com:6543/postgres`
   - берётся в Supabase → *Project Settings → Database → Connection string → URI*.
3. Разверни схему и наполни каталог одной командой:
   ```bash
   python -m pip install -r requirements.txt
   python setup_fresh_supabase.py
   ```
4. Готово — база собрана (таблицы + каталог 22 направления → 320 подкатегорий).

## Вариант B — обнулить существующую (старую) базу

Если нужно почистить именно ту же базу, что уже используется.

### Шаг 1. Заполни `.env`
Скопируй `.env.example` → `.env`, укажи `DATABASE_URL` старой базы.

### Шаг 2. Сброс всех таблиц проекта
Любой из способов (оба делают одно и то же — дропают только таблицы этого
проекта в схеме `public`, служебные объекты Supabase не трогают):

**Через Python (спросит подтверждение):**
```bash
python reset_database.py
# либо без вопросов:
python reset_database.py --yes
```

**Либо через psql / SQL Editor в Supabase:**
```bash
psql "$DATABASE_URL" -f reset_database.sql
```
В Supabase Dashboard можно просто открыть **SQL Editor**, вставить содержимое
`reset_database.sql` и нажать Run.

### Шаг 3. Собрать базу заново
```bash
python setup_fresh_supabase.py
```

## Что именно создаёт `setup_fresh_supabase.py`

Всё идемпотентно (`CREATE TABLE IF NOT EXISTS` / `ON CONFLICT`), повторный
запуск не плодит дубликаты, а лишь обновляет названия. Порядок:

1. **Базовые таблицы** — `users`, `master_categories`, `categories`, `master_skills`.
2. **Схема маркетплейса** — `partners`, `partner_locations`, `partner_directions`,
   `services`, `bookings`, `payments`, `notifications`, `ai_*` и комиссионные ALTER-ы.
3. **Направления партнёров** (partner directions).
4. **Жизненный цикл партнёров** (partner lifecycle).
5. **Каталог** — 22 направления → 320 подкатегорий (ru / hy / en).

**Модель комиссии** (как в рантайме):
- направление (`master_categories`) → комиссия по умолчанию `on_top / 10` (обязательная стартовая настройка);
- подкатегория (`categories`) → `NULL` = наследует направление;
- услуга (`services`) → `NULL` = наследует подкатегорию/направление.
Ненулевое значение на любом уровне перебивает нижние; значение на услуге всегда главнее.

> Комиссия всегда считается от финальной согласованной цены переговоров.

## Частые грабли

- **Порт БД**: используй pooler-URL с портом **6543**, прямой 5432 на Supabase часто отваливается по соединениям.
- **Startup-миграции не удаляют данные.** Приложение при запуске только
  доводит схему (`ensure_*`), поэтому старые данные сами не исчезнут — для
  чистого старта нужен именно сброс (Вариант B) или новая база (Вариант A).
- **SSL**: для облачных баз подключение идёт с `sslmode=require` автоматически.
- **Каталог не обязателен для схемы**: если нужна только структура без данных
  каталога — можно закомментировать `seed_catalogue()` в `setup_fresh_supabase.py`.
